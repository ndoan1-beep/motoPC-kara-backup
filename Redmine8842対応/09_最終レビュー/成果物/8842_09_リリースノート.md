# 8842_09_リリースノート

最新更新時刻：　2026年10月27日00:00:00

## 1. 対象

| 項目 | 内容 |
|---|---|
| チケット | Redmine 8842 |
| 件名 | CCRでの「売変・廃棄の伝票取消でLogicalDelFlgがセットされる」という処理を修正 |
| 対象システム | CCR |
| 対象機能 | 売変・廃棄伝票取消 |
| 対象DB | `SARSlipHeader`, `SARSlipDetail`, `SARSlipHeaderError`, `SARSlipDetailError`, `CMCAccountBook` |

## 2. リリース内容

売変・廃棄伝票取消時に、元伝票およびエラートランを論理削除せず、元伝票を検索可能な状態で残すように変更する。取消時は新規赤伝を作成し、指定された数量・金額項目をマイナス値として登録することで元伝票と赤伝の合計が0になるようにする。

また、取消後の元伝票と新規赤伝は伝票検索画面で検索可能とし、修正ボタンを表示しない。大福帳 `CMCAccountBook` 関連の既存登録・更新経路は変更しない。

## 3. 主な変更点

| No | 変更点 | 内容 |
|---|---|---|
| 1 | 論理削除抑止 | 取消時に `SARSlipHeader`, `SARSlipDetail`, `SARSlipHeaderError`, `SARSlipDetailError` の `LogicalDelFlg` を `'1'` に更新しない。 |
| 2 | 赤伝作成 | 取消時に `SARSlipHeader`, `SARSlipDetail` へ新規赤伝を登録する。 |
| 3 | 数量・金額相殺 | 赤伝の `TotalQty`, `SlipTotalDisposalAmt`, `DisposalChangeQty`, `DisposalPriceAmt` をマイナス値にする。 |
| 4 | 訂正不可制御 | 元伝票と赤伝の `SlipRevisionFlg` を訂正不可相当に更新する。 |
| 5 | エラーヘッダ制御 | `SARSlipHeaderError.FixDate` を `9999/12/31` に更新する。 |
| 6 | 大福帳維持 | `CMCAccountBook` / `UpInsAccountBookNew` の処理は変更しない。 |

## 4. 変更ファイル

| ファイル | 変更概要 |
|---|---|
| `SalesChangeDisposalSlipInputUpdate_partial.cs` | 取消ボタン押下時の画面側 DataSet で `LogicalDelFlg` を `"0"` に維持する。 |
| `SalesChangeDisposalSlipEntryNewBusiness.cs` | 取消時に論理削除を行わず、赤伝作成、訂正不可更新、FixDate 更新を行う。 |
| `SalesChangeDisposalSlipEntryNewDataAccessComponent.cs` | 訂正不可更新SQL、FixDate 更新SQL、赤伝INSERT SQL、ParameterList を追加・更新する。 |

## 5. DB影響

| テーブル | 影響 |

| `SARSlipDetailError` | 論理削除しない。 |

## 8. ロールバック方針

リリース後に重大な問題が発生した場合は、変更対象3ファイルをリリース前版へ戻す。DBスキーマ変更は行っていないため、ロールバック対象はアプリケーションコードが中心となる。
