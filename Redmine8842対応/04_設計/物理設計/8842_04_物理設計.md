# 8842_04_物理設計

最新更新時刻：　2026年08月26日09:36:35

## 1. 目的

論理設計を既存アーキテクチャに合わせて、変更候補ファイル、クラス、メソッド、SQL、DBオブジェクト候補へ展開する。

## 2. 対象アーキテクチャ

| 層 | 既存構成 | 設計方針 |
|---|---|---|
| UI | ASP.NET WebForms | 取消入口は維持。検索結果の表示制御と訂正遷移再判定を変更候補にする。 |
| Facade | UIからBusinessへの中継 | 原則変更しない。 |
| Business | 業務ロジック、取消判定、赤伝登録、大福帳登録 | 主変更箇所。論理削除呼出抑止、訂正不可判定候補を整理する。 |
| DataAccess | Inline SQL / DbCommand | 論理削除SQL本体は削除せず維持。検索SQLは確認対象。 |
| DB | SQL Server 2019 | スキーマ変更は前提にしない。実構造は未確認。 |

## 4. Business層物理設計

### 4.1 論理削除抑止

| 対象メソッド | 現行 | 変更案 |
|---|---|---|
| `UpInsSlipNew(...)` | `CancelMode == Constants.OnFlag` の場合、`SlipUpdateMode = slipUpdateMode_Red` 後に通常テーブルの `UpdateDelFlg...New` を呼ぶ。 | `SlipUpdateMode = slipUpdateMode_Red` は維持し、売変・廃棄取消の場合は `UpdateDelFlgSARSlipHeaderNew` / `UpdateDelFlgSARSlipDetailNew` を呼ばない。 |
| `UpInsSlipErrorNew(...)` 周辺 | ErrorTable経路で `UpdateDelFlgSARSlipHeaderErrorNew` / `UpdateDelFlgSARSlipDetailErrorNew` を呼ぶ。 | Error系を対象に含める場合は同様に呼ばない。対象外の場合は現行維持。 |
| `UpInsSlipExecuteNew(...)` | `slipUpdateMode_Red` で `UpInsSlipExecuteForDenyNew` を呼ぶ。 | 変更しない。 |

### 4.2 推奨分岐イメージ

```text
if (workEntity.CancelMode == Constants.OnFlag)
  SlipUpdateMode = slipUpdateMode_Red
  if (Redmine8842対象外または論理削除が必要な経路)
    UpdateDelFlg...New()
  end if
  UpInsSlipExecuteNew(...) または既存後続経路で赤伝登録へ進む
else
  既存の通常更新
end if
```

実装時は、現行の後続赤伝登録呼出位置を崩さないこと。フェーズ3レビュー指摘により、論理削除呼出を抑止した結果、赤伝登録まで抑止されないことを重点確認する。
