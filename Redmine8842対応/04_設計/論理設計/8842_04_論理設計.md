# 8842_04_論理設計

最新更新時刻：　2026年08月26日09:36:35

## 1. 目的

Redmine 8842 の業務要件を満たすため、売変・廃棄伝票取消時の論理的な処理変更、業務判定、データ状態、訂正不可制御を定義する。

## 2. 業務要件と論理設計対応

| 受入条件 | 論理設計 |
|---|---|
| 元伝票が削除扱いにならない | 売変・廃棄取消時は元伝票の論理削除更新を行わない。 |
| 数量・金額が相殺される | 赤伝登録による反転データで相殺することを第一候補とし、対象項目の期待値を確認する。 |
| 元伝票を検索できる | 元伝票を論理削除しないことで検索対象に残す。検索SQLの `LogicalDelFlg` 条件は確認対象とする。 |
| 新規赤伝を検索できる | 現行の赤伝登録結果を検索対象にする。 |
| 元伝票・赤伝の修正ボタンを表示しない | 対象伝票の `SlipCorrectionAvailabilityFlg` を訂正不可相当に設定する。 |
| 元伝票・赤伝を訂正選択不可にする | 画面表示制御に加え、訂正遷移時にサーバー側で再判定する。 |
| 大福帳連携を維持する | DataID判定、赤伝大福帳生成、登録処理を変更しない。 |

## 3. 対象伝票判定

| 条件 | 内容 |
|---|---|
| 取消モード | `workEntity.CancelMode == Constants.OnFlag` |
| 対象伝票種別 | AP変数で取得する売変伝票種別、廃棄伝票種別 |
| 赤伝モード | 取消時は `workEntity.SlipUpdateMode = slipUpdateMode_Red` |
| 対象外 | 売変・廃棄以外の伝票取消、通常登録、通常訂正 |

設計上、論理削除抑止は「取消モード」かつ「売変または廃棄伝票」を満たす場合だけに限定する。

## 4. 伝票状態設計

| データ | 取消前 | 取消後 |
|---|---|---|
| 元伝票ヘッダー | `SARSlipHeader` に存在 | `LogicalDelFlg` を更新せず、検索可能な状態で残す。 |
| 元伝票明細 | `SARSlipDetail` に存在 | `LogicalDelFlg` を更新せず、検索可能な状態で残す。 |
| 新規赤伝 | 未作成 | `UpInsSlipExecuteForDenyNew` で作成する。 |
| 大福帳 | 現行登録済みまたは登録対象 | 現行と同じDataID、タイミングで赤伝大福帳を登録する。 |
| 訂正可否 | 通常条件に従う | 元伝票・赤伝とも訂正不可にする。 |

## 5. 論理削除抑止設計

| 対象 | 現行 | 変更後 |
|---|---|---|
| `SARSlipHeader` | `UpdateDelFlgSARSlipHeaderNew` で `LogicalDelFlg = '1'` | 売変・廃棄取消時は呼び出さない。 |
| `SARSlipDetail` | `UpdateDelFlgSARSlipDetailNew` で `LogicalDelFlg = '1'` | 売変・廃棄取消時は呼び出さない。 |
| `SARSlipHeaderError` | `UpdateDelFlgSARSlipHeaderErrorNew` で `LogicalDelFlg = '1'` | Error系を要求対象に含める場合は呼び出さない。対象外の場合は現行維持。 |
| `SARSlipDetailError` | `UpdateDelFlgSARSlipDetailErrorNew` で `LogicalDelFlg = '1'` | Error系を要求対象に含める場合は呼び出さない。対象外の場合は現行維持。 |

Error系については、現行呼出が存在するため設計候補として通常系と同じ方針にする。ただし、業務対象に含めるかは未確認事項として残す。

## 6. 赤伝登録設計

| 項目 | 設計 |
|---|---|
| モード設定 | 取消時は現行通り `SlipUpdateMode = slipUpdateMode_Red` を設定する。 |
| 登録処理 | `UpInsSlipExecuteNew` の `slipUpdateMode_Red` 分岐から `UpInsSlipExecuteForDenyNew` を呼び出す。 |
| 論理削除との関係 | 論理削除更新をスキップしても、赤伝登録処理は必ず実行する。 |
| 相殺 | 赤伝登録による数量・金額の反転またはマイナスデータで相殺する前提とする。 |

## 7. 数量・金額相殺設計

| 区分 | 対象候補 | 設計扱い |
|---|---|---|
| ヘッダー数量 | `TotalQty` | 元伝票と赤伝の合計で相殺確認する。 |
| 売変金額 | `SlipOldTotalPrice`, `SlipNewTotalPrice`, `SalesChangePrice` | 赤伝側の符号、合計値を確認する。 |
| 廃棄金額 | `SlipTotalDisposalAmt`, `DisposalPriceAmt` | 赤伝側の符号、合計値を確認する。 |
| 明細数量 | `DisposalChangeQty` | 元伝票と赤伝の数量関係を確認する。 |

現時点では相殺期待値が未確定のため、フェーズ5以降で売変・廃棄それぞれの期待値表を作成する。

## 8. 訂正不可制御設計

| 制御箇所 | 設計 |
|---|---|
| 検索結果データ | 元伝票・赤伝に対して `SlipCorrectionAvailabilityFlg = "0"` 相当を返す。 |
| 画面表示 | 現行の `SlipCorrectionAvailabilityFlg == "0"` による修正ボタン非表示を利用する。 |
| 直接遷移 | `GridView_ItemCommand` または訂正画面入口で対象伝票の訂正不可を再判定する。 |
| 判定対象 | 取消後の元伝票、取消により作成された赤伝。 |

## 9. 大福帳連携設計

| 項目 | 設計 |
|---|---|
| 売変 | `DataId "03"` または `"02"` の現行判定を維持する。 |
| 廃棄 | `DataId "04"` と、廃棄時の売変DataID `"03"` 側赤伝作成経路を維持する。 |
| 赤伝大福帳 | `GenerateRedAccountBookDataSetNew` の `CorrectionDiv = "-"` と符号反転を維持する。 |
| 登録 | `RegisterAccountBookForJournal` の呼出を維持する。 |
