# 8842_04_画面制御設計

最新更新時刻：　2026年08月26日09:36:35

## 1. 目的

伝票検索画面で、取消後の元伝票と新規登録赤伝を検索可能にしつつ、修正ボタン非表示および訂正選択不可を実現する画面制御を設計する。

## 2. 対象画面・処理

| 対象 | 内容 |
|---|---|
| 伝票検索結果画面 | 売変・廃棄伝票検索結果の一覧表示、修正ボタン制御 |
| `SalesChangeDisposalSlipSearchResult_partial.cs` | 修正ボタン表示制御、訂正遷移処理 |
| `SalesChangeDisposalSlipSearchBusiness.cs` | 検索結果取得、検索結果加工候補 |
| `SlipHeaderListDataSet.xsd` | 検索結果列、`SlipCorrectionAvailabilityFlg` |

## 3. 現行制御

| 制御 | 現行内容 |
|---|---|
| 修正ボタン列 | 検索結果1列目に修正ボタンを持つ。 |
| 在庫月度制御 | `DisposalChangeDate(yyyyMM) < stockMonthly` の場合、修正ボタンを非表示。 |
| 訂正可否フラグ | `SlipCorrectionAvailabilityFlg == "0"` の場合、修正ボタンを非表示。 |
| 訂正遷移 | 修正ボタン押下時、選択行キーをセッションに格納して訂正画面へ遷移。 |

## 4. 変更後制御方針

| 対象 | 制御方針 |
|---|---|
| 取消後の元伝票 | 検索結果に表示する。ただし `SlipCorrectionAvailabilityFlg = "0"` 相当とする。 |
| 新規登録赤伝 | 検索結果に表示する。ただし `SlipCorrectionAvailabilityFlg = "0"` 相当とする。 |
| 修正ボタン | 現行制御を活用し、対象行では非表示にする。 |
| 直接遷移 | 修正ボタン非表示だけに依存せず、訂正遷移時にサーバー側で再判定する。 |

## 5. 訂正不可判定候補

| 判定要素 | 内容 | 状態 |
|---|---|---|
| 取消後元伝票判定 | 取消対象伝票で、赤伝登録済みの元伝票か判定する。 | 未確定 |
| 赤伝判定 | `UpInsSlipExecuteForDenyNew` で作成された赤伝か判定する。 | 未確定 |
| `SlipCorrectionAvailabilityFlg` | `"0"` の場合に修正不可。 | 現行利用あり |
| 在庫月度 | 過去月度は既存どおり修正不可。 | 現行維持 |

元伝票と赤伝の関連付け項目、赤伝判定項目は未確認のため、フェーズ5で実装候補を詳細化する。

## 6. 画面表示設計

| 項目 | 設計 |
|---|---|
| 元伝票表示 | 論理削除しないため検索対象に残す。検索条件で除外される場合は検索SQL側を調整候補にする。 |
| 赤伝表示 | 現行赤伝登録結果を検索対象にする。 |
| 修正ボタン | 対象行の `SlipCorrectionAvailabilityFlg` が `"0"` になるようにし、既存非表示制御を利用する。 |
| 表示文言 | 新規文言追加は本フェーズでは設計しない。既存画面デザインを維持する。 |

## 7. サーバー側制御設計

| 処理 | 設計 |
|---|---|
| `GridView_ItemCommand` | `SlipCorrectionButton` 押下時、選択行が訂正不可対象か確認する。 |
| 訂正不可の場合 | セッション設定や訂正画面遷移を行わない。必要に応じて既存のメッセージ表示方式に従う。 |
| 訂正可の場合 | 現行どおりセッションを設定し、訂正画面へ遷移する。 |
