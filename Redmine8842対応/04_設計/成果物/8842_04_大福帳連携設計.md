# 8842_04_大福帳連携設計

最新更新時刻：　2026年08月26日09:36:35

## 1. 目的

売変・廃棄伝票取消時に、元伝票の論理削除を抑止しても、大福帳連携の既存登録・更新動作を維持するための設計を定義する。

## 2. 現行大福帳処理

| 区分 | 現行内容 |
|---|---|
| 売変 | AP変数で売変伝票種別を取得し、`DataId "03"` または `"02"` を使用する。 |
| 廃棄 | AP変数で廃棄伝票種別を取得し、`DataId "04"` を使用する。 |
| 廃棄時の売変大福帳 | 廃棄時に売変DataID `"03"` 側の赤伝作成経路がある。 |
| 赤伝大福帳 | `GenerateRedAccountBookDataSetNew` で赤伝用データを作成する。 |
| 登録 | `RegisterAccountBookForJournal` を呼び出す。 |
| 赤伝符号 | `CorrectionDiv = "-"`、物流/商流区分の反転を行う。 |

## 3. 連携維持方針

| 項目 | 方針 |
|---|---|
| 呼出順 | 現行の大福帳呼出順を維持する。 |
| DataID | `DataId "03"` / `"04"` の現行取得処理を変更しない。 |
| 赤伝大福帳 | `GenerateRedAccountBookDataSetNew` の処理を維持する。 |
| 登録方式 | `RegisterAccountBookForJournal` を維持する。 |
| 論理削除抑止との関係 | 元伝票の `LogicalDelFlg` 更新抑止が大福帳登録のスキップ条件にならないようにする。 |

## 4. 設計対象メソッド

| ファイル | メソッド | 設計 |
|---|---|---|
| `SalesChangeDisposalSlipEntryNewBusiness.cs` | `UpInsAccountBookNew` | 原則変更しない。呼出が維持されることを確認する。 |
| 同上 | `GenerateAccountBookDataSetNew` | 黒伝側データ生成を現行維持する。 |
| 同上 | `GenerateRedAccountBookDataSetNew` | 赤伝大福帳データ生成を現行維持する。 |
| 同上 | `CopyAccountBookDataSetNew` | 既存利用がある場合は現行維持する。 |

## 5. DataID設計

| 伝票 | DataID | 設計 |
|---|---|---|
| 売変実績 | `"03"` | 現行取得を維持。対象環境で `SAR003` に解決されるか確認する。 |
| 売変その他 | `"02"` | AP変数条件に従う現行取得を維持。 |
| 廃棄 | `"04"` | 現行取得を維持。 |
| 廃棄時売変側赤伝 | `"03"` | 現行経路を維持。 |
