## 04_サイクル1_プロンプト

最新更新時刻：　2026年08月20日12:57:55

# チケット番号:
Redmine 8842

# 作業種別:
設計

# 目的:
売変・廃棄の伝票取消時に、元伝票を論理削除せず、赤伝登録・数量金額相殺・伝票検索画面での訂正不可制御・大福帳連携維持を実現するため、フェーズ2調査結果およびフェーズ3影響分析結果をもとに、実装可能な論理設計・物理設計・処理フローを整理する。

# 背景:
フェーズ2調査では、現行の売変・廃棄伝票取消処理において、取消モード時に赤伝登録経路へ入る一方で、元伝票に対して `LogicalDelFlg = '1'`、`LogicalDelDate` などを更新する論理削除処理が存在することが確認された。

Redmine 8842 では、売変・廃棄の伝票取消時に元伝票を論理削除せず、赤伝登録によって数量・金額を相殺し、元伝票と赤伝の両方を検索可能にする必要がある。また、取消後の元伝票および赤伝は伝票検索画面から訂正不可とし、大福帳連携は現行どおり維持する必要がある。

フェーズ3の成果物レビューは後続で実施予定のため、この設計フェーズでは、フェーズ3成果物が存在する場合は参照し、未作成またはレビュー未完了の事項は「前提」「仮定」「未確認事項」として明記する。

# 対象機能:
- 売変伝票入力
- 廃棄伝票入力
- 売変・廃棄の伝票取消処理
- 赤伝登録処理
- 数量・金額相殺処理
- 伝票検索画面の検索表示および訂正不可制御
- 大福帳連携処理
- 売変・廃棄に関連するDB更新、DataSet、DataAccess SQL

# 作業範囲:
- フェーズ2調査成果物と、存在する場合はフェーズ3影響分析成果物を読み、設計の前提・制約・未確認事項を整理する。
- 売変・廃棄の伝票取消時に、元伝票の `SARSlipHeader` / `SARSlipDetail` / `SARSlipHeaderError` / `SARSlipDetailError` を論理削除しないための分岐条件、対象メソッド、変更点を設計する。
- 現行の赤伝登録処理を維持するため、取消モード、赤伝モード、登録順序、既存呼出関係、トランザクション境界を整理する。
- 元伝票と赤伝による数量・金額相殺を成立させるため、対象項目、符号、計算タイミング、DB反映方針、既存処理流用可否を整理する。
- 伝票検索画面で元伝票と赤伝を検索可能にしつつ、取消済み伝票を訂正不可にするため、検索SQL、表示項目、`SlipCorrectionAvailabilityFlg`、画面制御、サーバー側制御の設計を行う。
- 大福帳連携について、現行の `DataId "03"` / `"04"`、赤伝大福帳作成、連携データ作成タイミングを維持する設計を行う。
- DB接続できない場合は、MCP `query_database_architecture` の結果、DataAccess SQL、DataSet定義、既存ソースを根拠にDB設計を整理し、実DB確認が必要な事項を未確認事項として分離する。
- 変更対象外の伝票種別、共通処理、既存業務仕様へ影響を広げないためのガード条件を設計する。
- 後続の `05_実装計画` フェーズでタスク分解できる粒度で、対象ファイル、対象メソッド、変更内容、確認観点を整理する。
