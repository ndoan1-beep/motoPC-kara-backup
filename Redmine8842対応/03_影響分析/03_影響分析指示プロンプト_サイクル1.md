## 03_サイクル1_プロンプト

最新更新時刻：　2026年08月18日17:50:53

# チケット番号:
Redmine 8842

# 作業種別:
影響分析

# 目的:
売変・廃棄の伝票取消時に、元伝票を論理削除せず、赤伝登録・数量金額相殺・伝票検索画面での訂正不可制御・大福帳連携維持を実現するため、フェーズ2調査結果をもとに変更影響範囲、リスク、回帰テスト範囲、後続設計で扱うべき論点を明確化する。

# 背景:
フェーズ2調査では、現行の売変・廃棄伝票取消処理において、`CancelMode == Constants.OnFlag` の場合に `SlipUpdateMode = slipUpdateMode_Red` が設定され、赤伝登録経路に入る一方で、元伝票の `SARSlipHeader` / `SARSlipDetail` / `SARSlipHeaderError` / `SARSlipDetailError` に `LogicalDelFlg = '1'`、`LogicalDelDate`、`UpdateBy`、`UpdateDate` を更新する処理が確認された。

また、伝票検索画面では `SlipCorrectionAvailabilityFlg == "0"` または在庫月度条件で修正ボタンを非表示にする現行制御があり、大福帳連携では `DataId "03"` / `"04"` を使った登録経路と赤伝大福帳作成処理が確認された。

現在DB接続はできないため、DB関連の影響はMCP `query_database_architecture` の結果、DataAccess SQL、DataSet定義を根拠として整理する。

# 対象機能:
- 売変伝票入力
- 廃棄伝票入力
- 売変・廃棄の伝票取消処理
- 赤伝登録処理

- 伝票検索画面
- 大福帳連携処理
- 売変・廃棄に関連するDB更新、DataSet、DataAccess SQL

# 作業範囲:
- フェーズ2調査成果物を読み、取消時の論理削除更新を止める場合の影響範囲を整理する。
- `UpdateDelFlgSARSlipHeaderNew` / `UpdateDelFlgSARSlipDetailNew` / `UpdateDelFlgSARSlipHeaderErrorNew` / `UpdateDelFlgSARSlipDetailErrorNew` の呼出抑止または条件分岐による影響を分析する。
- 赤伝登録 `UpInsSlipExecuteForDenyNew` を維持するために必要な分岐条件、呼出順、依存処理を整理する。
- 数量・金額相殺の対象候補項目、対象テーブル、仕様未確定事項、設計論点を整理する。
- 伝票検索画面で元伝票と新規赤伝を検索可能にしつつ訂正不可にするため、`SlipCorrectionAvailabilityFlg`、検索SQL、画面制御、サーバー側制御の影響を分析する。
- 大福帳連携について、`DataId "03"` / `"04"`、赤伝大福帳、`CMCDataIDControl`、`CMCAccountBook_SAR001` 関連候補への影響を整理する。
- DB接続不可の前提で、MCP `query_database_architecture`、DataAccess SQL、DataSet定義から確認できた範囲と、DB接続後に確認すべき範囲を分ける。
- 売変・廃棄以外の伝票取消処理、共通処理、回帰確認が必要な範囲を整理する。
- 影響範囲を UI / Facade / Business / DataAccess / DB / 連携 / テスト の観点で分類する。
