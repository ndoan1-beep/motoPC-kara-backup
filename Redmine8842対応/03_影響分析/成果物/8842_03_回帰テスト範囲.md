# 8842_03_回帰テスト範囲

最新更新時刻：　2026年08月20日13:04:16

## 1. 目的

Redmine 8842 の変更に対し、後続フェーズでテストケース化すべき回帰テスト範囲を整理する。

## 2. テスト観点サマリー

| 観点 | 優先度 | 確認内容 |
|---|---|---|
| UI取消操作 | High | 売変・廃棄の伝票取消操作が従来通り実行できること。 |
| DB更新 | High | 元伝票の `LogicalDelFlg` / `LogicalDelDate` が更新されないこと。 |
| 赤伝登録 | High | 取消時に新規赤伝が登録されること。 |
| 数量・金額相殺 | High | 元伝票と赤伝の数量・金額が期待値どおり相殺されること。 |
| 伝票検索 | High | 元伝票と新規赤伝の両方を検索できること。 |
| 訂正不可制御 | High | 元伝票と新規赤伝の修正ボタンが非表示、または訂正選択不可であること。 |
| 大福帳連携 | High | `DataID = SAR003` 相当および廃棄関連の大福帳登録・更新が既存通りであること。 |
| Error系 | Medium | ErrorTable経路を要求対象に含める場合、通常系と同様に確認すること。 |
| 他伝票回帰 | Medium | 売変・廃棄以外の取消処理に副作用がないこと。 |

## 4. DB確認観点

| 確認対象 | 確認項目 | 期待 |
|---|---|---|
| `SARSlipHeader` | `LogicalDelFlg`, `LogicalDelDate`, `UpdateBy`, `UpdateDate` | 取消対象の元伝票に論理削除更新が入らないこと。 |
| `SARSlipDetail` | `LogicalDelFlg`, `LogicalDelDate`, `UpdateBy`, `UpdateDate` | 取消対象の元伝票明細に論理削除更新が入らないこと。 |
| `SARSlipHeaderError` | 同上 | Error系を対象に含める場合、通常系と整合すること。 |
| `SARSlipDetailError` | 同上 | Error系を対象に含める場合、通常系と整合すること。 |
| `SARSlipHeader` / `SARSlipHeaderError` | `TotalQty`, `SlipOldTotalPrice`, `SlipNewTotalPrice`, `SlipTotalDisposalAmt` | 相殺期待値どおりであること。 |
| `SARSlipDetail` / `SARSlipDetailError` | `DisposalChangeQty`, `SalesChangePrice`, `DisposalPriceAmt` | 相殺期待値どおりであること。 |
| `CMCAccountBook` | `DataID`, `CorrectionDiv`, 伝票キー、金額・数量系項目 | 既存の大福帳登録・更新動作が維持されること。 |

## 5. テストデータ観点

| データ | 必要理由 |
|---|---|
| 売変取消可能な通常伝票 | 論理削除抑止、赤伝登録、相殺、検索、訂正不可確認に必要。 |
| 廃棄取消可能な通常伝票 | 廃棄固有の大福帳、廃棄金額相殺確認に必要。 |
| 在庫月度境界の伝票 | 既存在庫月度による修正不可制御の回帰確認に必要。 |
| ErrorTable対象データ | Error系を対象に含める場合の確認に必要。 |
| 売変・廃棄以外の取消可能伝票 | 副作用確認に必要。 |
