# 00_概要ルール 利用案内

## 目的

このフォルダーは、Redmineチケットまたは変更要求を受け付けた直後に使用する入力管理フォルダーです。
後続フェーズ（調査、影響分析、設計、実装、テスト、証跡、最終レビュー）へ進む前に、要求内容、作業範囲、成果物、受入条件、未確認事項を明確にします。

## このフォルダーの位置づけ

- 添付資料、既存ドキュメント、画面キャプチャ、過去スレッドは参考情報として扱います。
- 実際に実行すべき指示は、ユーザーからの最新依頼と本フォルダーで整理された合意事項を優先します。
- 不明点がある場合は、推測で実装や文書生成を開始せず、`未確認事項・決定事項.md` に記録します。

## 必須ファイル

| ファイル | 役割 |
|---|---|
| `ワークフロールール.md` | 全体の進行ルール、フェーズゲート、禁止事項を定義する。 |
| `プロンプト作成ルール.md` | AIエージェントまたは作業者へ依頼する際の標準プロンプト形式を定義する。 |
| `要求受付.md` | 要求内容、背景、対象機能、期待動作を整理する。 |
| `範囲と制約.md` | 作業範囲、対象外、制約、前提条件を定義する。 |
| `受入条件.md` | 受入条件をテスト可能な形で定義する。 |
| `成果物ルール.md` | 成果物の配置、命名、形式、文字コードを定義する。 |
| `追跡管理表.md` | 要求、設計、実装、テスト、証跡の対応関係を管理する。 |
| `未確認事項・決定事項.md` | 未確認事項、判断待ち、決定済み事項を管理する。 |
| `資料マッピングテーブル.md` | 各フェーズの入力資料と出力資料を対応付け、作業開始・完了時の確認基準を定義する。 |

## フェーズ2へ進む条件

フェーズ2（リポジトリと文書の調査）へ進む前に、最低限以下を完了していること。

- 要求概要が記載されている。
- 作業範囲と対象外が記載されている。
- 受入条件がテスト可能な形で記載されている。
- 作成または更新すべき成果物が記載されている。
- 重大な未確認事項がない、または未確認事項をリスクとして明示している。

## 運用ルール

- このフォルダーの内容は、後続フェーズの基準情報として扱います。
- 後続フェーズで新しい事実が判明した場合は、該当ファイルを更新し、変更理由を記録します。
- 既存成果物と矛盾がある場合は、矛盾点を明示し、どちらを正とするかを決めてから作業を継続します。
