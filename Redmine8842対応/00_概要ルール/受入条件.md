# 受入条件

## 1. 目的

要求が完了したと判断するための条件を、テスト可能な形で定義します。
各受入条件は、設計、実装、テストケース、証跡と対応付けます。

## 4. 受入条件の品質基準

良い受入条件は、以下を満たします。

- 期待結果が明確である。
- SQL、画面、ログ、ファイル、テスト結果などで確認できる。
- 曖昧な表現を含まない。
- 1つの条件に複数の期待動作を詰め込みすぎない。
- 失敗時に原因を分析できる粒度である。

## 6. 完了判定

以下を満たす場合、受入条件を満たしたと判断します。

- 各受入条件に対応するテストケースが存在する。
- テストケースの期待結果が受入条件と一致している。
- テスト実行結果がOKである。
- 証跡ファイルまたは実行ログで結果を確認できる。
- 失敗または保留がある場合、その理由と対応方針が記録されている。
