# TC-15 TestProcess Prompt

チケット番号:
Redmine #8842

作業種別:
テスト（Playwright UI）

目的:
確認画面なし設定の場合、伝票取消ボタン押下により `DelSARSlipNew` 相当の取消処理が即時実行され、完了メッセージ `MSGCSARI0028` が表示されることをPlaywrightで確認する。

背景:
Redmine #8842の変更後仕様では、確認画面なし設定の場合に確認画面を挟まず取消処理を実行する。実行後は、元伝票を論理削除せず、新規赤伝を登録し、一覧では元伝票と赤伝を検索可能かつ修正不可にする必要がある。

対象機能:
- 売変・廃棄伝票入力画面 伝票取消
- `SalesChangeDisposalSlipInputUpdate.SlipDeleateButton_Click`
- `DelSARSlipNew`
- 伝票検索画面 `SCRCBYR040205`

参照すべき資料:
- `Redmine_8842_テスト仕様書.md` の `TC-15`
- `Redmine8842.UnitTests/TestData.md` の 10行目（最新確定データ / TD-02相当）
- `Redmine8842_テストケース_流れ.md` の `Flow 14`

前提データ:
- `TestData.md` 10行目（TD-02）の保存済み売変伝票を取消対象として用意する。
- 主な対象データ:
- `@StoreCd = 035`
- `@SlipTypeCd = 07`
- `@SlipDiv = 02`
- `@SlipNo = 010000017`
- 元伝票 `@SlipBranchNo = 1`
- 赤伝 `@RedSlipBranchNo = 2`
- `@DisposalChangeDate = 2026-07-24`
- `SAR_CheckDisplay_Off` により直接実行する設定にする。設定値の名称とON/OFFの意味が環境で分かりにくい場合は、確認画面へ遷移しない実動作を基準にして記録する。

Playwright作業範囲:
- 既存のPlaywright構成を確認し、既存のテスト配置・fixture・認証方式に合わせて `TC-15` 用のUIテストを作成または実行する。
- 取消ボタン押下後に確認画面へ遷移しないこと、完了メッセージが表示されること、取消後状態が一覧で確認できることを検証する。
- DB確認はTC-02からTC-13相当の最小セットを実施する。

テスト手順:
1. Playwrightで対象アプリへアクセスし、必要に応じてログインする。
2. 確認画面なし設定であることを確認する。
3. 売変・廃棄伝票入力画面で、保存済み伝票 `010000017` を開く。
4. 取消前のDB状態を取得する。少なくとも元伝票の件数、`LogicalDelFlg`、赤伝枝番の有無を記録する。
5. 伝票取消ボタンを押下する。
6. 確認画面 `SCRCSAR050208` へ遷移しないことを確認する。
7. 完了メッセージ `MSGCSARI0028` または同メッセージに対応する完了文言が表示されることを確認する。
8. DB確認で、元伝票が `LogicalDelFlg = '0'` のまま残り、新規赤伝が作成されていることを確認する。
9. 伝票検索画面 `SCRCBYR040205`、またはカバーシート経由の一覧で対象伝票を検索する。
10. 元伝票と赤伝の両方が一覧表示され、両方とも「修正」操作が表示されないことを確認する。

主な期待結果:
- 取消ボタン押下後、`DelSARSlipNew` 相当の取消処理が即時実行される。
- 確認画面 `SCRCSAR050208` へ遷移しない。
- 完了メッセージ `MSGCSARI0028` が表示される。
- TC-02からTC-13相当の取消後状態になる。
- 元伝票と赤伝が検索可能で、両方とも修正不可になる。

証跡:
- 取消対象伝票を開いた画面スクリーンショット。
- 取消実行後の完了メッセージ `MSGCSARI0028` のスクリーンショット。
- 確認画面へ遷移していないことを示すURLまたは画面IDのログ。
- 取消前後のDB確認SQLと実行結果。
- 一覧検索結果と修正不可状態のスクリーンショット。
- Playwright trace、video、または実行ログ。

- 既存アプリケーションコードは変更しない。

完了条件:
