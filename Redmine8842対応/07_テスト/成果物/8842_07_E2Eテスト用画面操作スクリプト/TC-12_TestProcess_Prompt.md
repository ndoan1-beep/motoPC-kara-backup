# TC-12 TestProcess Prompt

チケット番号:
Redmine #8842

作業種別:
テスト（Playwright UI）

目的:
取消済みの元伝票と新規登録赤伝について、伝票検索画面またはカバーシート経由の一覧に「修正」ボタンが表示されず、修正画面へ遷移できないことをPlaywrightで確認する。

背景:
Redmine #8842の変更後仕様では、取消後も元伝票と赤伝を一覧検索可能にするが、両方とも訂正不可にする必要がある。判定条件は `SlipRevisionFlg = '1'` および `FixDate = '9999/12/31'` の更新結果に従う。

対象機能:
- 伝票検索画面 `SCRCSAR050306002`
- カバーシート経由の伝票一覧
- 一覧行の「修正」ボタン表示制御
- 修正画面遷移制御

参照すべき資料:
- `Redmine_8842_テスト仕様書.md` の `TC-12`
- `Redmine8842.UnitTests/TestData.md` の 10行目（最新確定データ / TD-02相当）
- `Redmine8842_テストケース_流れ.md` の `Flow 12`
- `Redmine_8842_変更仕様書.md` の伝票検索画面 `SCRCBYR040205` に関する記載

前提データ:
- `TestData.md` 10行目（TD-02）の保存済み売変伝票が取消済みであること。
- 主な検索キー:
- `@StoreCd = 035`
- `@SlipTypeCd = 07`
- `@SlipDiv = 02`
- `@SlipNo = 010000017`
- 元伝票 `@SlipBranchNo = 1`
- 赤伝 `@RedSlipBranchNo = 2`
- `@DisposalChangeDate = 2026-07-24`
- DB上では元伝票と赤伝が `LogicalDelFlg = '0'` のまま検索対象として残っていること。

Playwright作業範囲:
- 既存のPlaywright構成を確認し、既存のテスト配置・fixture・認証方式に合わせて `TC-12` 用のUIテストを作成または実行する。
- 一覧行単位で「修正」ボタン、修正リンク、編集アイコンなど同等の修正操作が表示・有効化されていないことを検証する。
- 表示テキストが環境差で異なる場合でも、「修正」相当の操作導線がないことを確認する。

テスト手順:
1. Playwrightで対象アプリへアクセスし、必要に応じてログインする。
2. 伝票検索画面 `SCRCBYR040205`、またはカバーシート経由の対象伝票一覧を開く。
3. 店舗 `035`、伝票種別 `07`、伝票区分 `02`、伝票番号 `010000017`、売変・廃棄日 `2026-07-24` で検索する。
4. 検索結果一覧に、元伝票と新規登録赤伝の両方が表示されることを確認する。
5. 元伝票行に「修正」ボタン、修正リンク、編集アイコンなど修正操作が表示されないことを確認する。
6. 新規登録赤伝行に「修正」ボタン、修正リンク、編集アイコンなど修正操作が表示されないことを確認する。
7. 行クリック、ダブルクリック、行選択後のツールバー操作などで修正画面へ遷移できる導線が残っていないことを確認する。
8. DB確認で、訂正不可制御の根拠となる `SlipRevisionFlg = '1'` および `FixDate = '9999/12/31'` を確認する。

主な期待結果:
- 元伝票行に「修正」ボタンが表示されない。
- 新規登録赤伝行に「修正」ボタンが表示されない。
- 修正画面へ遷移できない。
- 元伝票と赤伝は一覧から消えず、TC-11相当の検索可能状態は維持される。

証跡:
- 元伝票と赤伝の両方が表示された一覧スクリーンショット。
- 各行に「修正」操作が表示されていないことが分かるスクリーンショット。
- 修正画面へ遷移できないことを示すPlaywright trace、video、または実行ログ。
- `SlipRevisionFlg` と `FixDate` のDB確認結果。

制約:

完了条件:
