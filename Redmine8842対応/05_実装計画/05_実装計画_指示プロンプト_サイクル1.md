# 目的:

- 伝票検索画面の検索表示および訂正不可制御
- 大福帳連携処理
- 売変・廃棄に関連するDB更新、DataSet、DataAccess SQL

# 作業範囲:
- フェーズ4設計成果物の存在と内容を確認する。
- フェーズ4設計成果物が不足している場合は、不足資料を未確認事項として記録し、フェーズ2・3成果物を暫定根拠として実装計画を作成する。
- 実装対象ファイル、クラス、メソッド、DataSet、SQL、DBオブジェクト候補を一覧化する。
- 売変・廃棄取消時に元伝票の論理削除更新を抑止するための実装候補を整理する。
- `UpdateDelFlgSARSlipHeaderNew` / `UpdateDelFlgSARSlipDetailNew` / `UpdateDelFlgSARSlipHeaderErrorNew` / `UpdateDelFlgSARSlipDetailErrorNew` の扱いを、呼出抑止、条件分岐、既存用途維持の観点で整理する。
- 赤伝登録 `UpInsSlipExecuteForDenyNew`、`SlipUpdateMode = slipUpdateMode_Red`、大福帳登録経路を維持するための実装順序を整理する。
- 伝票検索画面で元伝票と赤伝を検索可能にし、訂正不可にするための修正候補を整理する。
- `SlipCorrectionAvailabilityFlg`、修正ボタン非表示、訂正画面への直接遷移抑止の実装候補を整理する。
- 数量・金額相殺について、設計で確定済みの対象項目・期待値を実装タスクへ展開する。未確定の場合は未確認事項として残す。
- DB接続不可の場合は、MCP `query_database_architecture`、DataAccess SQL、DataSet定義を根拠にSQL変更計画を作成し、実DB確認が必要な箇所を分離する。
- 実装順序、レビュー観点、テスト観点、ロールバック観点を整理する。
