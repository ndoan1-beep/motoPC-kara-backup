# ファイル変更計画

出典: `Redmine_8842_コード修正プラン.md`

## 目的

「売変・廃棄の伝票取消」時の動作を以下へ変更する。

1. 元伝票を論理削除しない。
2. `SARSlipHeader` / `SARSlipDetail` に同一伝票番号の新規赤伝を登録する。
3. 指定された数量・金額項目だけを赤伝INSERT時にマイナス化する。
4. 伝票検索画面で元伝票と新規赤伝を検索可能にする。
5. 検索可能だが、元伝票と新規赤伝のどちらも「修正」ボタンを表示しない。
6. 大福帳 `CMCAccountBook` の登録・更新動作は既存仕様から変えない。

## 変更計画

### 1. UI: `SlipDeleateButton_Click`

取消ボタン押下時、Dataset上のエラートランに `LogicalDelFlg = "1"` をセットしない。

修正方針:

- `SARSlipHeaderError` Dataset の `LogicalDelFlg` を `"0"` に維持する。
- `SARSlipDetailError` Dataset の `LogicalDelFlg` を `"0"` に維持する。
- 未保存伝票チェック、確認画面遷移、`workEntity.CancelMode = Constants.OnFlag`、取消後一覧再表示は変更しない。
- 後続のBusiness、大福帳処理へ論理削除前提のデータを渡さない。

### 2. Facade: `DelSARSlipNew`

Facadeは変更しない。

維持する内容:

- `TranUpdateMode = "1"`
- `UpInsSlipNew` 呼び出し
- 引数、戻り値、`FacadeMethod` ID

### 3. Business: `UpInsSlipErrorExecuteNew`

取消モードでエラートランを論理削除しない。

修正方針:

- `UpdateDelFlgSARSlipHeaderErrorNew` を呼び出さない。
- `UpdateDelFlgSARSlipDetailErrorNew` を呼び出さない。
- `FixDate = '9999/12/31'` の更新は、赤伝INSERT後に `UpdateFixDateSARSlipHeaderErrorNew` で行う。
- 通常更新時の `UpInsSARSlipHeaderErrorNew` / `UpInsSARSlipDetailErrorNew` は既存通り維持する。

### 4. Business: `UpInsSlipNew`

取消モードで本伝票を論理削除せず、赤伝を作成してから訂正不可更新を行う。

修正方針:

- `UpdateDelFlgSARSlipHeaderNew` を呼び出さない。
- `UpdateDelFlgSARSlipDetailNew` を呼び出さない。
- `UpInsSlipExecuteForDenyNew(workEntity, dsEntity)` を呼び、新規赤伝を作成する。
- 赤伝INSERT後に `UpdateSlipRevisionFlgSARSlipHeaderNew(workEntity, dsEntity)` を呼び出す。
- 赤伝INSERT後に `UpdateFixDateSARSlipHeaderErrorNew(workEntity, dsEntity)` を呼び出す。
- `workEntity.SlipUpdateMode = slipUpdateMode_Red` を維持する。
- `UpInsAccountBookNew` の内部ロジックは変更しない。

### 7. DAO: `UpdateSlipRevisionFlgSARSlipHeaderNew` 追加

目的:

- 元伝票と新規赤伝を伝票検索画面で検索可能にしたまま、訂正選択不可にする。

追加メソッド:

```csharp
public virtual void UpdateSlipRevisionFlgSARSlipHeaderNew(WorkEntity workEntity, DsEntity dsEntity)
```

実行SQL方針:

```sql
UPDATE SARSlipHeader
   SET SlipRevisionFlg = '1',
       UpdateBy = @UpdateBy,
       UpdateDate = @UpdateDate
 WHERE CorporationCode = @CorporationCode
   AND SlipDiv = @SlipDiv
   AND SlipTypeCd = @SlipTypeCd
   AND SlipNo = @SlipNo
   AND DisposalChangeDate = @DisposalChangeDate
   AND StoreCd = @StoreCd
   AND LogicalDelFlg = '0'
```

補足:

- `SlipBranchNo` は条件に入れない。
- 元伝票と新規赤伝の両方に `SlipRevisionFlg = '1'` を付けるため。
- 共通更新項目は既存 `SetCommonItemForUpdateNew` を使う。

### 8. DAO: `UpdateFixDateSARSlipHeaderErrorNew` 追加

目的:

- `SARSlipHeaderError.FixDate = '9999/12/31'` に更新し、エラートラン側でも訂正不可状態を表現する。

追加メソッド:

```csharp
public virtual void UpdateFixDateSARSlipHeaderErrorNew(WorkEntity workEntity, DsEntity dsEntity)
```

実行SQL方針:

```sql
UPDATE SARSlipHeaderError
   SET FixDate = '9999/12/31',
       UpdateBy = @UpdateBy,
       UpdateDate = @UpdateDate
 WHERE CorporationCode = @CorporationCode
   AND SlipDiv = @SlipDiv
   AND SlipTypeCd = @SlipTypeCd
   AND SlipNo = @SlipNo
   AND DisposalChangeDate = @DisposalChangeDate
   AND StoreCd = @StoreCd
```

補足:

- `UpdateDelFlgSARSlipHeaderErrorNew` と同じ検索条件を使用する。
- `LogicalDelFlg` / `LogicalDelDate` は更新しない。
- `SARSlipDetailError` は更新しない。
- 共通更新項目は既存 `SetCommonItemForUpdateNew` を使う。
