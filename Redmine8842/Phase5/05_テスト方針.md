# 05_テスト方針

出典: `Redmine_8842_テスト仕様書.md`

## テスト目的

売変・廃棄伝票の取消時に、従来の論理削除ではなく、元伝票を残したまま新規赤伝を登録する仕様へ変更されていることを確認する。

確認の中心は以下とする。

- 元伝票、エラートランを論理削除しないこと。
- `SARSlipHeader` / `SARSlipDetail` に新規赤伝が登録されること。
- SQLで指定された数量・金額項目だけがマイナス値で登録されること。
- 元伝票と新規赤伝が画面一覧で検索できること。
- 元伝票と新規赤伝に対して「修正」ボタンが表示されず、訂正不可になること。
- `SARSlipHeader.SlipRevisionFlg` と `SARSlipHeaderError.FixDate` が訂正不可判定として仕様通り更新されること。
- 大福帳 `CMCAccountBook` の `DataID = '003'` 登録・更新動作が既存仕様から変わらないこと。

## 共通前提

- 取消対象の売変または廃棄伝票が保存済みであること。
- `SARSlipHeaderError` に対象伝票が存在すること。
- `SARSlipDetailError` に対象伝票明細が存在すること。
- `SARSlipHeader` に対象伝票の本伝票ヘッダが存在すること。
- `SARSlipDetail` に対象伝票の本伝票明細が存在すること。
- 対象伝票の `LogicalDelFlg` はすべて `'0'` であること。

## 重点確認方針

### 1. 未保存伝票の取消防止

保存されていない伝票を取消しようとした場合は、エラーメッセージ `ERRCSARB0273` が表示され、`SARSlipHeaderError` / `SARSlipDetailError` / `SARSlipHeader` / `SARSlipDetail` に更新・INSERTが発生しないことを確認する。

### 2. 論理削除しないこと

取消後も以下が維持されることを確認する。

- `SARSlipHeaderError.LogicalDelFlg = '0'`
- `SARSlipDetailError.LogicalDelFlg = '0'`
- `SARSlipHeader.LogicalDelFlg = '0'`
- `SARSlipDetail.LogicalDelFlg = '0'`

### 3. 赤伝登録

取消後、`SARSlipHeader` に新規赤伝ヘッダ、`SARSlipDetail` に新規赤伝明細が作成されることを確認する。

赤伝では以下を重点確認する。

- `SlipBranchNo` が元伝票と重複しないこと。
- `RedBlackDiv` が赤伝を示す値であること。
- `LogicalDelFlg = '0'` で登録されること。

### 4. マイナス化対象項目

仕様で指定された項目だけがマイナス化されることを確認する。

- ヘッダ: `TotalQty`, `SlipTotalDisposalAmt`
- 明細: `DisposalChangeQty`, `DisposalPriceAmt`

また、元伝票と赤伝の合計が0になることを確認する。

### 5. 訂正不可更新

取消後、訂正不可を表す更新が行われることを確認する。

- `SARSlipHeader.SlipRevisionFlg = '1'`
- `SARSlipHeaderError.FixDate = '9999/12/31'`

### 6. 画面検索・修正ボタン

伝票検索画面またはカバーシート経由で対象伝票を検索し、以下を確認する。

- 元伝票が一覧に表示されること。
- 新規登録赤伝が一覧に表示されること。
- 両方とも `LogicalDelFlg = '0'` のデータとして確認できること。
- 元伝票行に「修正」ボタンが表示されないこと。
- 新規登録赤伝行に「修正」ボタンが表示されないこと。
- 修正画面へ遷移できないこと。

### 7. カバーシート再集計

取消後に `SARCoverSheetMaster` が更新され、以下が現行ロジック通り再計算されることを確認する。

- `TotalPageQty`
- `InputPageCount`
- `ErrorNo`
- `ApprovalCount`

カバーシートの `LogicalDelFlg` は変更しないこと。

### 8. 確認画面あり・なし

確認画面ありの場合は、取消ボタン押下時点ではDB更新を行わず、確認画面で確定後に取消処理が実行されることを確認する。

確認画面なしの場合は、`DelSARSlipNew` が即時実行され、取消後のDB更新・赤伝登録・訂正不可更新が完了することを確認する。

### 9. 承認済み伝票・大福帳

`ApprovalStatus = '3'` の伝票取消でも、赤伝ヘッダ・明細の作成、訂正不可更新が行われることを確認する。

大福帳 `CMCAccountBook.DataID = '003'` の登録・更新動作は既存仕様から変わらないことを確認する。

## 回帰確認方針

以下の既存操作が従来通り動作することを確認する。

| No | 確認観点 | 期待結果 |
|---|---|---|
| 1 | 通常の新規保存 | 既存通り保存できる |
| 2 | 通常の修正保存 | 既存通り赤黒伝が作成される |
| 3 | 明細追加 | 既存通り明細追加できる |
| 4 | 明細削除 | 既存通り明細削除できる |
| 5 | 売変伝票取消 | 論理削除せず赤伝が登録される |
| 6 | 廃棄伝票取消 | 論理削除せず赤伝が登録される |
| 7 | カバーシート検索後の取消 | 取消後に一覧再表示できる |
| 8 | 伝票検索後の取消 | 取消後に一覧再表示できる |
| 9 | 取消後の検索 | 元伝票と新規登録赤伝が検索できる |
| 10 | 取消後の修正 | 元伝票と新規登録赤伝の修正ボタンが表示されない |
| 11 | 大福帳 `DataID = '003'` の登録・更新 | `CMCAccountBook` の登録・更新動作が既存仕様から変わらない |
