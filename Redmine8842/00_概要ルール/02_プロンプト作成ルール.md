# プロンプト作成ルール

## 1. 目的

AIエージェントまたは作業者へ依頼する際の入力形式を標準化し、曖昧な依頼による手戻りを減らします。
このファイルに従って依頼を整理してから、調査、設計、実装、テスト、証跡作成を開始します。

## 2. 標準プロンプト形式

```text
チケット番号:
作業種別:
  - 要件整理 / 調査 / 影響分析 / 設計 / 実装計画 / 実装 / テスト / 証跡 / 最終レビュー

目的:

背景:

対象機能:

対象リポジトリ・フォルダー:

参照すべき資料:

作成または更新する成果物:

作業範囲:

対象外:

受入条件:

制約:

禁止事項:

完了条件:

不明点がある場合の扱い:
```

## 3. 良い依頼の条件

- 目的が1文で説明できる。
- 対象機能、対象画面、対象バッチ、対象テーブルのいずれかが明記されている。
- 作成または更新すべき成果物が明記されている。
- 受入条件がテスト可能である。
- 対象外が明記されている。
- 不明点がある場合に、質問すべきか、仮定して進めるかが明記されている。

## 4. 避けるべき依頼例

```text
上のファイルを修正してください。
いい感じに資料を作ってください。
前と同じように対応してください。
全体を確認して必要なところを直してください。
```

## 5. 推奨依頼例

作成されたプロンプトには、`Redmine8842_01_要求受付_プロンプト`というファイルになって、妥当なフォルダ`./01_要求受付/`で保存されます。
```text
チケット番号:
Redmine 8842

作業種別:
要求受付

目的:
売変・廃棄伝票取消時に元伝票を論理削除せず、赤伝を登録する仕様変更の影響範囲を明確にする。

対象機能:
売変・廃棄伝票入力、伝票取消処理、伝票検索

参照すべき資料:
- 00_概要ルール/03_要求受付.md
- 00_概要ルール/05_受入条件.md

作成または更新する成果物:
- 03_影響分析/8842_03_影響分析.md
- 03_影響分析/8842_03_リスク一覧.md

作業範囲:
- UI、Facade、Business、DataAccessComponent、SQL、関連テーブルの影響確認

対象外:
- 未指定機能のリファクタリング
- UIデザイン変更
- DBスキーマ変更

完了条件:
対象ファイル、対象メソッド、対象テーブル、リスク、回帰範囲が一覧化されていること。
```

## 6. 不明点の扱い

- 受入条件に影響する不明点は、作業開始前に確認します。
- 軽微な表記ゆれや成果物名の調整は、作業者が合理的に判断してよいです。
- 判断した内容は `08_未確認事項・決定事項.md` の「決定済み事項」に記録します。
