# 追跡管理表

## 1. 目的

要求、設計、実装、テスト、証跡、最終レビューを対応付け、成果物間の不整合を防ぎます。

## 2. 管理単位

| 種別 | ID例 | 説明 |
|---|---|---|
| 要求 | REQ-001 | ユーザー要求またはチケット要求。 |
| 受入条件 | AC-001 | 完了判定に使う条件。 |
| 設計 | DSG-001 | 論理設計または物理設計の項目。 |
| 実装 | IMP-001 | 対象ファイル、クラス、メソッド、SQL。 |
| テスト | TC-001 | テストケース。 |
| 証跡 | EVD-001 | SQL結果、画面証跡、ログ、ビルド結果。 |
| レビュー | REV-001 | 最終確認項目。 |

## 7. 更新ルール

- 新しい要求、受入条件、設計項目、実装項目、テストケース、証跡を追加した場合は、本ファイルも更新します。
- 実装後に設計と異なる点が判明した場合は、設計または実装計画を更新し、本ファイルの対応関係も修正します。
- 最終レビュー時に、状態が未作成、未実施、保留の項目が残っていないか確認します。
